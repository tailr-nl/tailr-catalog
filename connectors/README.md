# Connectors

A connector tells Tailr Core how to reach a system: a single JSON file (`<id>.json`), or a folder with `connector.json`, `README.md`, `context.md` (guidance for the AI) and optional code functions in `tools/`. Code always runs in Tailr Core's sandbox: no network of its own, no secrets, only the calls listed in the manifest, with the caller's permissions.

`index.json` lists the connectors in this source, with their versions. Tailr Core reads it when an administrator refreshes the source.

## Two ways to connect the same system (`variantOf`)

A connection in Tailr Core belongs to the installation, not to a person. Where a system offers a **service account** (a technical account with a JSON key file), that is the recommended route: `auth` with `"type": "oauth2"`, `"flow": "jwt_bearer"` and `assertion.fromJsonKey` pointing at a secret, multi-line setting (`"multiline": true`) that holds the key file. There is no OAuth client, consent screen or sign-in that expires; Tailr Core signs in with the key itself.

Signing in with the administrator's own account can stay available as a **variant**: a second, complete connector with `variantOf` (the id of the main connector) and `variantTitle` (`{ "en": "Sign in with your own Google account", "nl": "…" }`). A variant is listed in `index.json` like any other connector, but Tailr Core does not show it separately under *Connections → Available*: it appears as an alternative route on the connect page of the main connector. Its functions (names and levels) must be identical to those of the main connector; `tailr check` warns when they differ. Examples: [google-analytics.json](google-analytics.json) with [google-analytics-signin.json](google-analytics-signin.json), and [google-search-console.json](google-search-console.json) with [google-search-console-signin.json](google-search-console-signin.json).

## Overview content (`presentation`)

A connector, plugin or structured translation file may provide `presentation.intro`, up to six `presentation.examples` (`prompt` and a non-empty `requires` list), and `presentation.whatsNew`. Text is English or `{ "en": "…", "nl": "…" }`; it is plain text, never HTML. Use `adminOnly: true` for administration content. No examples are generated by the core when these fields are absent.

A connector uses local function names in `requires`; a plugin or translation uses fully qualified names such as `dashboards__list`. A prompt is shown only when the user can access every required function through AI. News is one item per newly available module, not one per function. Raise the module version when changing content. Translations require the structured format with `messages`; keep their version in `translations/index.json`.

See the matching JSON schema in `schemas/` and the core documentation `docs/presentation.md`. The installed core must support `presentation` to display it; older cores ignore the optional metadata.
