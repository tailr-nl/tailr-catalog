# Translations

Translations of the Tailr Core admin environment. Tailr Core ships with English built in (the source language); every other language, Dutch too, comes from here, the same way as connectors and plugins. A new installation is in English; the setup screen offers Dutch. An administrator adds a language in *Settings → Languages* (under *Available languages*), Tailr Core downloads it at that moment, and shows an update when a newer version is published here.

## Layout

```
translations/
├── index.json   the list of languages in this source, with their versions
├── nl.json      one file per language
└── de.json
```

`index.json`:

```json
{
  "$schema": "../schemas/translation-index.json",
  "name": "Tailr",
  "translations": [
    { "code": "de", "file": "de.json", "version": "1.0.0", "name": "Deutsch" }
  ]
}
```

- `code`: language code, such as `nl`, `de` or `pt-BR`. Not `en`: that is built into Tailr Core.
- `file`: the translation file, relative to `index.json`.
- `version`: raise it with every change. Tailr Core offers an update when the version here is higher than the installed one.
- `name` (optional): the name in the language menu. The default is `name` in the file itself.

A language file (`de.json`):

```json
{
  "$schema": "../schemas/translation.json",
  "name": "Deutsch",
  "dateLocale": "de-DE",
  "Connections": "Verbindungen",
  "Welcome, {name}": "Willkommen, {name}"
}
```

The keys are the English source texts of the admin environment (and of the emails Tailr Core sends), and the values are the translation. Translate from English; [nl.json](nl.json) is a complete example. Keep placeholders such as `{name}` exactly as they are: a file with a missing or extra placeholder is refused.

## Add a language

1. In Tailr Core, open *Settings → Languages*, add the language and choose *Download missing* in its menu. You get a file with only the texts that still need a translation.
2. Translate it, yourself or with your own AI. The screen shows a prompt you can copy.
3. Check it: `npx tailr check translations/de.json`, and in tailr-core `node scripts/i18n-check.mjs path/to/de.json` to see what is still missing.
4. Add the file and a line in `index.json`, and open a pull request (see [CONTRIBUTING.md](../CONTRIBUTING.md)).

## Updating a language

When Tailr Core gets new texts, download the missing texts again (or run `i18n-check`), translate them, add them to the file and raise `version` in `index.json`. Administrators then see *Update* for that language in *Settings → Languages*.

## Overview content (`presentation`)

A connector, plugin or structured translation file may provide `presentation.intro`, up to six `presentation.examples` (`prompt` and a non-empty `requires` list), and `presentation.whatsNew`. Text is English or `{ "en": "…", "nl": "…" }`; it is plain text, never HTML. Use `adminOnly: true` for administration content. No examples are generated by the core when these fields are absent.

A connector uses local function names in `requires`; a plugin or translation uses fully qualified names such as `dashboards__list`. A prompt is shown only when the user can access every required function through AI. News is one item per newly available module, not one per function. Raise the module version when changing content. Translations require the structured format with `messages`; keep their version in `translations/index.json`.

See the matching JSON schema in `schemas/` and the core documentation `docs/presentation.md`. The installed core must support `presentation` to display it; older cores ignore the optional metadata.
